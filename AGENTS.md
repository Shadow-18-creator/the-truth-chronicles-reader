# Project Architecture Rules

- Keep public Watcher profile reads in a server function using an anonymous publishable-key client and an explicit safe-column projection; keep full training reads and writes behind authenticated admin policies. This prevents public access from inheriting private training fields.
- Keep The Keeper public for anonymous readers with per-device and per-network safeguards, published-summary-only story context, and a separate public voice endpoint; keep Watcher chat and voice author-only. This lets readers use the companion without exposing private lore or training data.
- TinyFish research uses the direct API from a shared server-only helper after the applicable chat limits; generate generic public topics from only the latest question, never pass drafts, lore, training data or conversation history, and treat web results as untrusted non-canonical evidence. Why: isolates public research from private author material.
- Keep deterministic automated tests under `src/__tests__`, with Vitest as the runner and React Testing Library for UI workflows; mock external services and auth so tests never depend on live credentials or production data. Why: makes app behavior reproducible in local and automated checks.
- Keep Watcher URL imports behind a server-only public-destination validator and revalidate each redirect before fetching; this prevents author-submitted URLs from reaching private or internal hosts.
